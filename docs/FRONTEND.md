# Platå frontend principles

Curated from [awesome-design](https://github.com/gztchan/awesome-design) and adapted for a static, plateau-first Danish learning site. Use this when changing `index.html`, lesson shells, or `styles.css`.

## Voice and positioning

- **Plateau-first:** Public copy speaks to A2–B2 learners who already know Danish but freeze under pressure. Lesson 01 is onboarding, not the headline hook.
- **Tagline:** *Break your Danish plateau.* Danish secondary: *Kom videre fra dit danske plateau.*
- **Serious, adult tone:** No gamification chrome, no mascot energy. Clarity beats delight.
- **One primary action per screen:** Hero, dashboard Today, and lesson scenes should make the next step obvious.

## Typography

References: [Butterick's Practical Typography](https://practicaltypography.com/), [Typewolf](https://www.typewolf.com/), Google Fonts pairing guides.

| Role | Font | Use |
|------|------|-----|
| Display | Fraunces | Headlines, lesson titles, emotional beats |
| UI / body | Inter | Nav, cards, forms, explanations |
| Code / data | JetBrains Mono | IDs, JSON hints, technical labels |

Rules:

- Keep body line length ~60–75 characters in prose blocks.
- Use weight contrast (500–650 display, 400–600 UI), not size alone, for hierarchy.
- Avoid more than two families on a page.

## Color and contrast

References: [Colorable](https://colorable.jxnblk.com/), limited palette discipline.

- **Background** `--bg` / `#202a24` — calm, not pure black.
- **Accent** `--peak` / sage greens — mountain metaphor, links, success.
- **Ember** — errors and high-attention warnings only.
- Check text on tinted cards (`--card`, `--muted`) before shipping; prefer WCAG AA for body copy.

## Layout and components

References: Mozilla, Atlassian, and IBM design language (structure, not visual clone).

- Reuse existing primitives: `.hero-grid`, `.trainer-card`, `.path-card`, `.btn`, `.section-head`.
- Grids collapse to one column at `max-width: 900px` — test mobile first for distribution links.
- Spacing rhythm: 16px gaps in grids, 22px card padding, consistent `section` vertical rhythm.
- Status and proof UI stay scannable: chips, short titles, one sentence of copy.

## UX habits

References: [UX Movement](https://uxmovement.com/), [Smashing Magazine](https://www.smashingmagazine.com/category/uxdesign/).

- **Progressive disclosure:** Evaluator path and program map are for inspectors; quick-start paths are for learners.
- **Feedback immediately:** Drills and lessons explain *why* after an attempt; don't hide the reason behind another click.
- **Respect privacy:** Say "stays in this browser" where LocalStorage matters.
- **Offline-friendly:** PWA shell should degrade gracefully; no blank screen when cached.

## Social and share surfaces

- `og:title`, `og:description`, and `og:image` must match the plateau tagline on the landing page.
- OG image: `assets/og-plata.png` (1200×630), generated by `npm run build:pwa-icons` — brand mark only; message lives in meta text.
- `twitter:card=summary_large_image` on pages we expect to share.

## User testing (when we distribute)

References: [Lookback](https://lookback.io/), [Hotjar](https://www.hotjar.com/) — use lightly once P5 posts go live.

- Watch one real learner pick a path from the home page without explanation.
- Note where they hesitate between Lesson 01, B2 lessons, and drills.
- Prefer copy fixes over new UI when hesitation is wording, not layout.

## What we do not do

- No SPA framework for the public site; catalog + static HTML stay the source of truth.
- No analytics pixels or third-party embeds on learner paths.
- No decorative animation without a learning purpose (register feedback, session receipt, etc. are fine).

## Checklist before shipping UI copy

1. Does the headline say *plateau*, not *beginner*?
2. Is there exactly one obvious CTA above the fold?
3. Do meta + manifest + README use the same tagline?
4. Does `npm run check` pass (including smoke-home / smoke-pwa)?
5. Mobile: quick-start cards readable without horizontal scroll?
